# 设计说明

这份文件记录"为什么这样写"，给以后改它的人（包括我自己）看。

## 1. 为什么是 `tools.guard`，不是别的层

DSH 的工具执行链有几处可以插手，按侵入性从弱到强：

| 机制 | 能做什么 | 为什么没用 |
| --- | --- | --- |
| `tools.restrict()` | 把工具从 agent 视野里拿掉 | 太粗：禁掉 `pwsh` 等于废掉 agent |
| `tools/pre-execute`（waterfall） | 可以改写、可以 `ask` | `ask` 依赖审批通道；审批关掉时会 fail closed，等于装了个"永远说不"的死锁（实测踩过） |
| **`tools.guard()`（本插件）** | 同步拒绝，返回字符串即否决 | 只能拒绝、不能"改写成安全版本"——够用，且不依赖审批 |
| `subprocess.spawn` | 最底层，覆盖所有进程 | 误杀面从"一条命令"扩大到"整台机器"，写错的代价是所有 agent 起不了进程 |

选 guard 的核心原因：**它不依赖任何外部通道**。审批关着、网络断了、插件别的部分坏了，它照样工作。

## 2. 为什么是"拒绝"而不是"询问"

询问听起来更温和，但有两个坑：

- 审批策略是会话级的（`ask` / `never`）。用户在 `never` 下，`ask` 会直接失败——命令被拒，但用户看不到任何提示，
  只会觉得"这插件莫名其妙坏了"。实测过一次，很难排查。
- 询问把决定权交回给"当下想删东西的那个模型"。它已经决定要删了，再问一遍，大概率还是"是"。

拒绝则把决定权交给**规则文本**：消息里写着"改成什么、为什么"。这比"你确定吗"更有信息量。

## 3. 为什么同时有黑名单和白名单

- 黑名单（`rd /s`、`rm -rf`…）是**精确打击**：误伤少，但永远列不全——没人会把"盘根"写进禁止清单，
  而事故恰恰发生时目标是盘根。
- 白名单（只有工具目录里的脚本能跑）是**结构约束**：不依赖"我知道哪些命令危险"，
  只依赖"这些目录我信"。列不全的问题被绕开了。

两者叠加：黑名单负责常见形态，白名单负责"没预料到的那条路"。

## 4. 为什么 `cmd /c` 一律拒

它不是删除命令，但它是一层**封装**：外面看到的只是一个字符串，里面是批处理/管道/变量展开。
放过它就等于承认"我允许看不见内容的东西执行"。这条规则的成本很低（正常命令直接写就好），
收益是把最常见的绕过路径堵死。

## 5. 为什么脚本只查"命令位"

最初的版本扫全串，结果 `Set-Content x.ps1 -Value ...` 也被拦——写文件又不是执行。
改成只看每条命令的首 token（以及 `start` / `call` / `-File` 之后的那个），
`Set-Content`、`Out-File`、重定向写文件都不再误伤，而 `.\x.cmd`、`x.ps1`、`powershell -File x.ps1` 仍然拦得住。

## 6. 为什么不读脚本内容做静态分析

读文件、找 `rm -rf`、判断"安全"——听起来更聪明，但：

- guard 是**同步**的，读文件会拖慢每一次工具调用；
- 静态分析不可靠，误判"安全"比不分析更糟（用户会以为检查过了）；
- 脚本可以动态生成命令，读内容也读不出来。

所以边界划在"看不懂就不执行"，而不是"我猜它是安全的"。

## 7. 配套工具为什么不用系统回收站

系统回收站有**配额**。超过配额的删除，Windows 会**静默地变成永久删除**——不提示、不进回收站、
`SHFileOperation` 照样返回成功。这正好把"可逆"变成"不可逆"，而且是无声的。

隔离区是纯改名（同卷 `rename`）：原子、秒级、不占额外空间、不受配额影响。代价是它不会出现在
资源管理器的回收站里，得用 `--list` 看。这个交换是值得的。

## 8. 失败模式

| 坏了什么 | 表现 | 后果 |
| --- | --- | --- |
| 插件加载失败 | 命令照常跑 | 静默失去保护——所以要求"装完自测一条 `Remove-Item -Recurse`" |
| 正则写错（过严） | 正常命令被拒 | 烦，但安全；拒绝消息会指路 |
| 正则写错（过松） | 漏掉某类删除 | 危险；靠 README 的自测清单补 |
| `tools.guard` 接口变化 | 插件抛错或静默不生效 | 升级后必须重新自测 |

结论：**它是护栏，不是地基**。地基是沙箱（目录边界）和备份（不在删除范围内）。

## 9. 明确不做的事

- 不做"自动改写命令"（guard 只能拒绝，改写需要 waterfall，会引入顺序依赖）
- 不做跨 profile 分发
- 不做日志轮转（交给用户/外部工具）
- 不把"询问"作为默认行为
